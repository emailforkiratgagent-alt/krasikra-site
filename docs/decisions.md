# Решения и статус

Короткий журнал принятых решений и открытых вопросов. Новое решение — новая строка; устаревшее не удаляем, а помечаем.

Обновлено: 31.10.2026.

## Бизнес-правила

| Тема | Решение |
|---|---|
| Роль сайта | Третий клиент X.Label рядом с приложениями iOS/Android. Каталог, цены, наличие, заказы, оплата, бонусный баланс — только из X.Label. OpenCart выводится из работы. |
| Магазин | Всё (ассортимент, цены, наличие) считается от одного магазина: при доставке — ближайший к адресу по прямой (`/stores/nearest`), при самовывозе — выбранный покупателем из 10. Енисей не учитываем. |
| Цены | Показываются после входа и выбора адреса/магазина, как в приложении. До этого — каталог без цен (для SEO). Технически API отдаёт цены без входа, это решение бизнеса. |
| Вход | Telegram, WhatsApp, Max (без SMS). Гостевых заказов нет. |
| Оплата | Только онлайн, Сбер, двухстадийно: холд при оформлении, списание при вручении (`received`). Вес весового товара оператор меняет в админке X.Label не больше заказанного. Бонусы и купоны в онлайн-заказах не используются. |
| Доставка | Яндекс Go через X.Label. Цена — заявка Яндекса (`by_request`), пересчёт через `calc` перед заказом, если истёк `valid_until`. Курьера вызывает оператор отдельным действием. Интервалы и часы работы — в админке X.Label. |
| Чек | Пробивает касса магазина. |
| Неоплаченные заказы | Никто не отменяет, остаются в X.Label как `not_payed`. Сайт проверяет оплату в фоне до 30 мин, в кабинете показывает «Оплатить». |
| Остатки | «Камчатка» обновляет каждое утро; нет остатка — `allow_to_sell = false`, товар не показывается. Дневную нехватку решает оператор. |
| Отмена заказа покупателем | Нет в API — «позвоните для отмены». |

## Технические решения

| Тема | Решение |
|---|---|
| Стек | Next.js + Payload CMS 3, PostgreSQL, TypeScript. Один контейнер (сайт + админка `/admin`). |
| Хостинг | Yandex Cloud Serverless Containers, тестовый стенд — см. `docs/infra/test-stand.md`. |
| API | X.Label Mobile API 1.30, `platform=web`, отдельный токен сайта (`webAppToken`). |
| Доступ к X.Label | Только с сервера сайта (BFF). Токены приложения, покупателей и `id_token` входа в браузер не попадают. |
| Настройки интеграции | Адрес API, токен сайта, публичный ключ — в админке («Интеграция X.Label»), только роль администратора; токен в БД зашифрован, в UI маскируется. |
| `hash_code` | UUID v4 браузера в долгоживущей httpOnly-cookie, шифруется на сервере ключом сайта: RSA-2048, OAEP, SHA-256, MGF1 SHA-256, base64. |
| Сессия | Отдельная httpOnly-cookie. `access_token` 1 год, `refresh_token` бессрочный и одноразовый — обновлять по 401 «Access token has expired.», строго по очереди на покупателя. |
| Вход | Опрос `/token/{provider}` 2 с → 5 с, не дольше `expires_in` (3600 с), привязан к браузеру-инициатору. `id_token` одноразовый. |
| Цены в заказе | X.Label сверяет цену каждой позиции, суммы, доставку. Сайт считает так же: цена магазина (`price`, акционная уже в ней), сумма позиции = `round(кол-во × цена)` до копеек (половина вверх). |
| Каталог/CMS | ID товаров X.Label стабильны — CMS привязывается к ним. Синхронизация по `/versions` без токена покупателя; поля X.Label перезаписываются, поля CMS — никогда. Slug не меняется после создания. Фото кешируем у себя. |
| Смена CMS | Доступ к контенту через свой слой (`getProductContent`, `getPage`…), не напрямую к Payload. |
| Выкатка на стенд | GitHub Actions: каждый PR собирается и проверяется, `main` автоматически выкатывается на тестовый стенд. Вход в Yandex Cloud через федерацию удостоверений (OIDC), ключей в GitHub нет; выкатывать может только ветка `main`. |
| Секреты | Yandex Lockbox, секрет `krasikra-web-test` → переменные окружения контейнера (`PAYLOAD_SECRET`, `SETTINGS_ENCRYPTION_KEY`, позже `DATABASE_URI`). В репозитории и в GitHub секретов нет. |
| База данных (разработка) | Стартового гранта нет, поэтому до каркаса кода базы на стенде нет. Когда появится код: временно PostgreSQL на маленькой прерываемой ВМ в Yandex Cloud (≈400–500 ₽/мес), перед запуском — переезд на Managed PostgreSQL (≈5,8 тыс. ₽/мес, s3-c2-m8). Зарубежные бесплатные базы не используем (152-ФЗ). |

## Открытые вопросы

- Режим шлюза Сбера (`sberEcommerceMode` / `securepayments`) — к этапу 2, SberPay Web.
- Повторяют ли приложения `/token/{provider}` при сетевой ошибке (одноразовый токен).
- Веб-лицензия шрифта DIN Pro у заказчика — или бесплатная замена.
- Фото продукции для сайта (съёмка ассортимента в фирменном стиле).
- Тестовые учётные данные Сбера для «Тест Камчатка» и проверка `use_two_stage: true`.
