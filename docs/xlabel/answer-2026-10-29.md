Дата ответа: 29.10.2026. Код всех четырёх задач готов, влит в основную ветку и выложен (pull request №93). Для проекта «Тест Камчатка» токен и ключ сайта выпущены, осталось заполнить адреса возврата для оплаты (см. ниже).

Порядок 1 → 3 → 2 соблюдён. Новых методов API нет. Миграций три, все добавляют необязательные колонки, поведение приложений iOS и Android не меняется.

Проверено автоматическими тестами X.Label (221 тест, включая новые на каждую задачу). **Не проверено:** работа с настоящим тестовым контуром Сбера и вид страницы оплаты на компьютере — это проверяется только в проекте-копии после настройки.

## Задача 1. Платформа `web`

- `GET /settings`, `GET /versions`, `POST /orders/{id}/payments/init` принимают `platform=web`. Для `web` `/settings` отдаёт те же способы входа, что для Android. Любое другое значение платформы по-прежнему даёт `{"error":"Wrong platform"}`.
- `GET /versions` с авторизацией записывает вход в `AppLogin` с платформой `web`.
- `POST /orders` принимает необязательное поле `platform` (`android`, `ios` или `web`); оно сохраняется в заказе. Не передано — поле пустое, как у старых клиентов. Другое значение — 400 `Wrong platform`.
- Для `web` не используется схема оплаты app2app (переход в приложение банка): она нужна только приложениям.

Что учесть сайту:
- `GET /versions` по-прежнему требует параметр `version` вида `1.2.3` (иначе `Wrong version`). Передавайте любую фиксированную версию сайта, например `1.0.0`.
- Push-токен для `web` не нужен.

## Задача 2. Адреса возврата и вёрстка страницы оплаты Сбера

- В настройках платёжной системы Сбера появились два поля: «URL возврата: успех» и «URL возврата: ошибка» (`webReturnUrl`, `webFailUrl`). В адресе подставляется `{order_id}`, например `https://krasikra.ru/order/{order_id}/success` и `https://krasikra.ru/order/{order_id}/fail`. Заполняет оператор в админке X.Label.
- `POST /orders/{id}/payments/init` с `platform=web` передаёт в Сбер эти адреса вместо `sberbank://success` и `sberbank://fail`. Если поля не заполнены — ответ 400 с текстом `Website return URLs are not configured for this payment system`, платёж не создаётся.
- Новый необязательный параметр `page_view`: `desktop` или `mobile` (регистр не важен). Он уходит в Сбер как `pageView`. Без параметра — `MOBILE`, как раньше. Другое значение — 400 `Wrong page_view`. Параметр действует для любой платформы, клиент сам выбирает вид страницы.
- Для `android` и `ios` ничего не изменилось.

## Задача 3. Отдельный токен и ключ `hash_code` для сайта

Уточнение к постановке: в X.Label у проекта был один токен `X-APP-TOKEN`, а в боевом проекте сайт и приложения будут в одном проекте. Поэтому у проекта появился **второй токен — токен сайта**. Какой ключ применять к `hash_code`, определяется тем, каким токеном пришёл запрос.

- Токен приложений и ключ приложений не меняются.
- С токеном сайта `hash_code` расшифровывается ключом сайта: **RSA-2048, схема OAEP, хеш SHA-256, MGF1 SHA-256**. Шифруется UUID v4 браузера (36 символов), результат передаётся в base64. Если после расшифровки не UUID v4, идентификатор считается недействительным.
- Тот же `hash_code` с токеном приложений не принимается, и наоборот: `hash_code` ключа приложений не принимается с токеном сайта.
- Токен сайта выпущен и заполнен для проекта «Тест Камчатка»; администратор X.Label видит его в админке (поле `webAppToken` проекта). Публичный ключ в формате PEM передаётся файлом `web_public.pem`. Для боевого проекта токен и ключ будут свои, отличные от тестовых.
- Вариант HMAC из постановки не делали: выбран RSA.

До выдачи ключа сайта в проекте-копии можно использовать токен и публичный ключ приложений (PKCS#1 v1.5), как было предложено.

## Задача 4. Одноразовый `id_token`

- После первого успешного ответа `/token/telegram`, `/token/max`, `/token/whatsapp` токен входа немедленно истекает. Повторный вызов с тем же `id_token` вернёт `401` с текстом **«Истек срок действия токена»** (не «Токен уже использован», как в постановке). Сайт уже обрабатывает этот текст как «остановить опрос и предложить войти заново».
- Если вход отклонён (например, пользователь заблокирован или превышен лимит устройств), токен не расходуется, и попытку можно повторить.
- Правило действует для всех клиентов, в том числе для приложений.
- Со своей стороны сайт хранит `id_token` только на сервере и привязывает опрос к браузеру, начавшему вход.

## Что нужно от команды сайта

1. Подтвердить параметры шифрования `hash_code` (RSA-OAEP, SHA-256, MGF1 SHA-256) и что UUID v4 берётся из cookie браузера.
2. Сообщить итоговые адреса возврата для проекта-копии и боевого проекта.
3. Принять к сведению: повторный вход по использованному `id_token` даёт «Истек срок действия токена»; `page_view` задаёт клиент.

## Что делает X.Label для запуска

1. Токен и ключ сайта для проекта «Тест Камчатка» выпущены (`webAppToken` в админке, публичный ключ в файле `web_public.pem`).
2. Адреса возврата для оплаты заполняются в админке X.Label, в настройках платёжной системы Сбера (`webReturnUrl`, `webFailUrl`), когда команда сайта сообщит итоговые адреса.
